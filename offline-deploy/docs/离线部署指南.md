# Open WebUI 内网离线部署手册（保姆级操作指南）

> 适用场景：内网服务器**无外网、无 Python/Node 环境，仅安装 Docker**。
> 目标：把 Open WebUI 以 Docker 镜像形式部署到内网，浏览器访问即可使用。
> 模型服务、Pipeline 服务已作为独立 Docker 服务部署在内网，Open WebUI 只做前端框架接入，**不需要下载任何模型**。
> 本文档按步骤手把手操作，每条命令都有"预期结果"和"排查方法"。

## 〇、整体流程（先看这个）

整个事情就 4 步：

```
第1步 打包：   在有网的电脑上，把代码打包成 Docker 镜像（一条命令，自动完成前端打包+后端依赖安装）
第2步 导出：   把镜像压缩成一个文件（open-webui-offline.tar.gz，约1.2GB）
第3步 搬运：   把这个文件拷到内网服务器（U盘/scp/ftp 都行）
第4步 部署：   内网服务器上 docker load 导入，然后 docker compose 启动，浏览器访问
```

**关键认知（为什么内网不用装 Python/Node）：**
- 打包时，Docker 会临时起一个 Node 容器打包前端、一个 Python 容器装后端依赖
- 这些都发生在**有网的打包机器**上，最终产物是一个"全家桶"镜像
- 内网服务器只是"加载 + 运行"这个镜像，所以只需要 Docker

项目代码目录：`/Users/lzh/Documents/work/open-webui`（以下命令都在这目录里执行）：

### 1.3 确认内网服务器架构（重要！）

内网服务器的 CPU 架构必须和镜像一致，否则跑不起来。在**内网服务器**上执行（`uname` 是系统自带命令，不需要装任何东西）：


| 输出 | 含义 | 打包时用的参数 |
|---|---|---|
| `x86_64` | Intel/AMD 架构（最常见） | `linux/amd64` |
| `aarch64` | ARM 架构（鲲鹏、飞腾等） | `linux/arm64` |

**先记住这个结果，下一步要用。**

## 二、在有网机器上打包（构建镜像）

### 2.1 一键打包脚本（推荐）

在代码目录执行，把 `linux/amd64` 换成第 1.3 步查到的架构：

```bash
cd /Users/lzh/Documents/work/open-webui

# x86_64 内网服务器用这条：
TARGET_PLATFORM=linux/amd64 ./scripts/build-offline-image.sh

# aarch64 内网服务器用这条：
TARGET_PLATFORM=linux/arm64 ./scripts/build-offline-image.sh
```

**脚本会做两件事**（日志会依次打印 `[1/3]`、`[2/3]`、`[3/3]`）：
1. `[1/3]` 构建镜像（最耗时，首次约 30~60 分钟，要联网下载依赖）
2. `[2/3]` 导出并压缩成 `open-webui-offline.tar.gz`
3. `[3/3]` 打印产物信息

**预期最终输出：**

```
>>> [3/3] 完成!
-rw-r--r--  1 lzh  staff   1.2G ... open-webui-offline.tar.gz
```

### 2.2 手动分步执行（如果脚本失败，用这个定位）

脚本其实就两句话，也可以手动一条条跑：

```bash
# 第一步：构建镜像（x86_64 示例）
docker build --platform linux/amd64 \
  --build-arg USE_OLLAMA=false \
  --build-arg DOWNLOAD_MODELS=false \
  -t open-webui:offline .

# 第二步：导出压缩
docker save open-webui:offline | gzip > open-webui-offline.tar.gz
```

### 2.3 构建参数说明

| 参数 | 值 | 作用 |
|---|---|---|
| `--platform` | `linux/amd64` 或 `linux/arm64` | **必须匹配内网服务器架构** |
| `--build-arg USE_OLLAMA=false` | 固定 false | 不需要 Ollama |
| `--build-arg DOWNLOAD_MODELS=false` | false 或 true | false=不下载 embedding/whisper 模型（纯聊天，默认）；true=下载烘焙进镜像（将来要 RAG 文档检索/语音转写时用） |

### 2.4 构建成功标志

```bash
docker images | grep open-webui
# 预期:
# open-webui  offline  7e5e6d51...  4.26GB
```

看到 `4.26GB` 左右的镜像就是成功了。构建日志末尾出现 `naming to docker.io/library/open-webui:offline done` 也代表成功。

> ⚠️ 构建需要联网（npm / pip / 模型仓库）。构建过程中如果网络中断报超时，**直接重跑同一命令即可**，已下载的部分有缓存，不会从头再来。

## 六、配置并启动服务

### 6.1 准备部署配置文件

把代码里的 `docker-compose.offline.yaml` 拷到内网服务器（或直接按下面内容创建）：

```bash
cd /opt/open-webui
vi docker-compose.offline.yaml
```

文件内容（**务必修改 `OPENAI_API_BASE_URLS` 和 `WEBUI_SECRET_KEY`**）：

```yaml
services:
  open-webui:
    image: open-webui:offline
    pull_policy: never
    container_name: open-webui
    restart: unless-stopped
    ports:
      - "3000:8080" # 宿主机端口:容器端口，左侧可改
    volumes:
      # bind mount: 数据直接落在宿主机 /root/data/open-webui, 方便备份和迁移
      - /root/data/open-webui:/app/backend/data # 数据持久化(数据库/上传文件/配置)
    environment:
      # === 模型服务(OpenAI 兼容 API) 和 Pipeline 服务，分号分隔多个地址 ===
      - 'OPENAI_API_BASE_URLS=http://模型服务IP:端口/v1;http://pipelineIP:端口/api/v1'
      # 与上面地址一一对应的 API Key，没有就留空字符串
      - 'OPENAI_API_KEYS=;'
      # 会话加密密钥，改成随机字符串（重要）
      - 'WEBUI_SECRET_KEY=改成一段随机字符串'
      # 不使用 RAG 知识库检索: 置为非空值可跳过启动时下载 embedding 模型(离线环境必设)
      - 'RAG_EMBEDDING_ENGINE=ollama'
    extra_hosts:
      - host.docker.internal:host-gateway
```

> **关于数据目录**：本手册用 bind mount 把数据固定到宿主机 **`/root/data/open-webui`** 目录（也可改成其他路径，如 `/opt/open-webui/data`）。**首次部署前必须先在宿主机创建该目录**，否则 Docker 会以 root 自动创建，属性和权限可能不是你想要的：
>
> ```bash
> mkdir -p /root/data/open-webui
> chmod 755 /root/data/open-webui   # 可选, 防止 root 之外访问
> ```
>
> 好处：`webui.db`（账号/聊天/配置）、上传文件等都直接落在这个目录下，备份直接 `tar` 打包目录即可，升级/迁移都不用 docker 命令。

### 6.2 地址怎么填（对照你的实际情况）

| 你的情况 | 写法 |
|---|---|
| 模型/pipeline 和 open-webui **在同一台内网服务器**（用 `-p 8000:8000` 之类端口映射暴露） | `http://host.docker.internal:8000/v1` |
| 在**另一台内网机器**上 | `http://那台机器内网IP:端口/v1` |
| 和 open-webui 在**同一个 docker 网络** | 服务名，如 `http://model-api:8000/v1` |

> 路径注意：OpenAI 兼容服务一般要带 `/v1`；Pipeline 服务一般是 `/api/v1`。填错会 404，可在容器日志看到。

### 6.3 启动

```bash
cd /opt/open-webui
# 首次部署先创建数据目录(若已按 6.1 创建可跳过)
mkdir -p /root/data/open-webui

docker compose -f docker-compose.offline.yaml up -d

# 预期输出:
# [+] Running 2/2
#  ✔ Network ...  Created
#  ✔ Container open-webui  Started
# 注意: 用 bind mount 不会出现 "Volume ... Created" 那行, 数据直接写宿主机目录
```

查看状态：

```bash
docker ps
# 预期: 有一行 open-webui，STATUS 是 Up ... (healthy)
```

## 八、日常使用与升级

### 8.1 停止 / 启动 / 查看日志

```bash
# 停止
docker compose -f docker-compose.offline.yaml down

# 重新启动
docker compose -f docker-compose.offline.yaml up -d

# 看日志（排查问题用）
docker logs -f open-webui

# 重启单个容器
docker restart open-webui
```

### 8.2 升级（数据不丢）

数据都存在宿主机目录 `/root/data/open-webui` 里（bind mount），升级不影响：

```bash
# ① 在有网机器上重新打包（改了代码后）
cd /Users/lzh/Documents/work/open-webui
TARGET_PLATFORM=linux/amd64 ./scripts/build-offline-image.sh
# 注意: 第二次构建有缓存，约 7 分钟

# ② 传输
scp open-webui-offline.tar.gz user@内网服务器:/opt/open-webui/

# ③ 内网服务器重新导入 + 重启
cd /opt/open-webui
docker load -i open-webui-offline.tar.gz
docker compose -f docker-compose.offline.yaml up -d
```

### 8.3 备份数据（可选）

bind mount 下备份最简单，直接打包目录即可，**不需要 docker 命令**：

```bash
# 备份（推荐: 先停容器再打包, 保证 SQLite 一致性）
docker compose -f /opt/open-webui/docker-compose.offline.yaml down
tar czf /root/open-webui-data-backup-$(date +%Y%m%d).tar.gz -C /root/data open-webui
docker compose -f /opt/open-webui/docker-compose.offline.yaml up -d
```

```bash
# 恢复/迁移: 把备份包拷到新机器的 /root 下解压即可
cd /root && tar xzf open-webui-data-backup-xxx.tar.gz   # 解出 /root/data/open-webui
# 然后照 6.3 启动容器
```

> SQLite 在线打包可能产生不一致备份。最稳妥的顺序：先 `docker compose down`（或 `docker stop open-webui`），再打包，再启动。若不想停机，可用 `docker exec open-webui sqlite3 /app/backend/data/webui.db ".backup /tmp/webui.db"` 后拷出该文件，但这只备份数据库、不含 uploads 等目录。

## 九、常见问题排查（FAQ）

| 现象 | 原因 | 解决办法 |
|---|---|---|
| 打包时 `npm ci` 报 "lock file's ... does not satisfy" | package-lock.json 和 package.json 不同步 | 有网机器上执行 `npm install --package-lock-only` 后再打包 |
| 打包时 `FATAL ERROR: Reached heap limit`（前端构建内存不足） | 容器 Node 默认堆内存不够 | 已修复：Dockerfile 里加了 `NODE_OPTIONS=--max-old-space-size=8192`，无需处理 |
| 打包时 pip 下载 torch 报 `TimeoutError` | 网络波动 | 直接重跑构建命令，有缓存 |
| 打包时 `Building for: default`（不是 bjny） | `.env.bjny` 没进构建上下文 | 已修复：`.dockerignore` 加了 `!.env.bjny`，无需处理 |
| 容器启动就退出，日志报 `ModuleNotFoundError` | requirements.txt 缺依赖 | 已修复：补了 `opencc`、`diskcache`。若新增代码再缺，参照"十"的排查法 |
| 内网启动容器时尝试联网拉镜像 | 用了原版 `docker-compose.yaml`（对 ollama 有 `pull_policy: always`） | 用 `docker-compose.offline.yaml` |
| 浏览器打开页面空白 / 502 | 服务还在启动（首次启动约 30~60 秒） | 等一会，`docker logs -f open-webui` 看是否报错 |
| 聊天时看不到模型 | 模型服务地址/路径不对 | 检查 `OPENAI_API_BASE_URLS`，看容器日志是否有 404/连接失败 |
| `docker load` 报空间不足 | 磁盘不够 | 镜像约 4.26GB，预留 15GB+ |

## 十、本次打包踩过的坑（已修复，记录备查）

| 问题 | 现象 | 修复 |
|---|---|---|
| lock 文件不同步 | `npm ci` 报 pyodide 版本不匹配 | `npm install --package-lock-only` 同步 |
| 前端构建 OOM | `FATAL ERROR: Reached heap limit Allocation failed` | Dockerfile 加 `NODE_OPTIONS=--max-old-space-size=8192` |
| `.env.*` 被排除 | Docker 构建 `Building for: default`，丢失 bjny 定制（页脚/APP_NAME） | `.dockerignore` 加 `!.env.bjny` |
| 缺 `opencc` | 启动报 `ModuleNotFoundError: No module named 'opencc'` | requirements.txt 补包 |
| 缺 `diskcache` | 启动报 `ModuleNotFoundError: No module named 'diskcache'` | requirements.txt 补包 |
| torch 下载超时 | pip `TimeoutError: The read operation timed out` | 网络波动，重试 |

**如果以后改代码又遇到 `ModuleNotFoundError`，排查方法（一次性找全所有缺失依赖）：**

```bash
# 在有网机器上，对已构建的镜像扫描所有顶层 import
cat > /tmp/scan_imports.py << 'EOF'
import ast, importlib, pathlib, sys
sys.path.insert(0, '/app/backend')
missing = set()
for p in pathlib.Path('/app/backend/open_webui').rglob('*.py'):
    try:
        tree = ast.parse(p.read_text())
    except Exception:
        continue
    for node in ast.walk(tree):
        names = []
        if isinstance(node, ast.Import):
            names = [a.name for a in node.names]
        elif isinstance(node, ast.ImportFrom) and node.module:
            names = [node.module]
        for n in names:
            top = n.split('.')[0]
            if top.startswith('open_webui'):
                continue
            try:
                importlib.import_module(top)
            except ModuleNotFoundError as e:
                missing.add(top)
            except Exception:
                pass
print("MISSING_MODULES:", sorted(missing))
EOF
docker run --rm --entrypoint bash -e WEBUI_SECRET_KEY=x \
  -v /tmp/scan_imports.py:/tmp/scan_imports.py open-webui:offline \
  -c "cd /app/backend && python /tmp/scan_imports.py 2>/dev/null"
# 输出 MISSING_MODULES: [...]，把结果中属于生产代码的包加进 requirements.txt
```
